# Линия силы — состояние проекта

Актуально на **2 ноября 2026 года**. Согласованный объём этапа 2 реализован в локальной ветке `codex/gymbot-explain-progression` от `355aab44e9689a2df42be9e52b4bb6c156041a04`. Production, webhook, реальные уведомления, PR, публикация и слияние не затрагивались.

## Результат этапа 2

- В тренировке и истории есть «Почему такой план?»: сохранённые источники, рабочие факты, медиана и округление веса, причины повторов/подходов, ограничения объёма и источник ПДО. Расчёт и объяснение используют одну серверную функцию; клиент не повторяет формулы.
- Подсказка следующего подхода объясняется отдельно по свежему факту, цели ПДО и шагу снимка. Она не меняет сохранённый план. Раскрытие деталей не делает запросов и не создаёт недель/занятий.
- Из программы убрано редактирование целевого ПДО. Лёгкая фаза имеет приоритет и назначает 4, возвращение в обычную фазу — 2,5, обычная фаза — 2. Фактический ПДО нового подхода пустой и обязателен для рабочего подхода; ноль сохраняется как факт, неизвестное значение не заменяется целью.
- Автоматическая цель повторов ограничена обеими границами диапазона. Факты и явные ручные цели не исправляются. Формула веса, выбор собственной базы и правила работы с разными рабочими весами сохранены.
- Ручные изменения отмечены отдельно от исходного расчёта. Они сохраняются при существующем явном переносе неначатого занятия; он пересчитывает автоматическую часть на новую дату. Для старых неопознанных ручных изменений происхождение не выдумывается.
- Старые снимки не получают вымышленных объяснений. Доступны прежние цели, факты и подписи; подробности расчёта неизвестны. Изменения программы/источника и просмотр не пересчитывают существующий план или его объяснение.
- Справка уточнена. Существующие палитра, типографика и обычная геометрия сохранены. Добавлены локальные стили деталей и исправлен минимальный размер страницы при 320 px с вертикальной полосой прокрутки.

## Контракты и совместимость

Новых маршрутов нет. `SessionExercise.recommendation` дополняет ответ существующего API занятия; `next_set.basis` показывает исходные значения текущей подсказки. В JSON версии 1 сохраняются версия правил, дата расчёта, входы, до трёх источников с рабочими фактами, причины веса/повторов/подходов/ПДО, `calculated` и `manual_override`. Ручной вес в объяснении совпадает с сохранённой точностью Numeric в БД.

Миграция **6** добавляет одну nullable-колонку `session_exercises.recommendation_context_json TEXT`; для старых строк остаётся NULL. Идентичности `id`/`slot_id`/`history_id` и записанные факты не меняются. Устаревший `Exercise.rir_target` остаётся в API/БД как `number | null`, не влияет на назначение; отсутствие поля при обновлении сохраняет прежнее, 0 и NULL различаются. Новый клиент поле не отправляет.

При параллельной разработке сохранить контракт миграции 6 и JSON версии 1, не выпускать другую миграцию под тем же номером. Сервер и клиент обновляются одной согласованной версией: старый код не обновляет объяснения и отметки ручных целей, поэтому чередовать версии на общей базе нельзя. До будущего изменения существующей базы обязательны проверенные резервная копия и восстановление. Проверки текущего этапа использовали только синтетические данные и собственные временные схемы.

Основные файлы: `backend/app/{planning,recommendations,main,serializers,schemas,models,migrations}.py`, `frontend/src/{RecommendationDetails,WorkoutView,HistoryView,ProgramView,App}.tsx`, `types.ts`, локальные стили `reference.css`; тесты `test_recommendations.py`, `test_recommendation_migration.py` и прежние миграционные сценарии. Зависимости, lockfile, настройки аутентификации, webhook и расписания не менялись. Команды и точные правила — в [README.md](README.md#объяснение-плана-и-пдо-этап-2).

## Как посмотреть и воспроизвести

Локальные снимки вне Git: `preview-stage2-plan-320.png`, `preview-stage2-manual-390.png`. Полный набор запускается командой из README с URL собственной тестовой PostgreSQL и `--basetemp=.venv/pytest-stage2`. Новый набор сценариев отдельно: `backend/tests/test_recommendations.py` и `backend/tests/test_recommendation_migration.py`.

В собственной синтетической preview-среде откройте созданную тренировку → «Почему такой план?»; сравните цели с сохранённым расчётом и рабочими источниками. Затем задайте ручную цель до записи результатов, запишите фактический ПДО 0 и сравните самостоятельную подсказку следующего подхода с неизменным планом. При просмотре старой истории подробности расчёта должны оставаться неизвестными. Не используйте для этого рабочие данные или команды, меняющие локальный webhook.

## Границы и следующий шаг

Прогрессия по-прежнему использует первый рабочий вес каждого занятия; веса остальных подходов не усредняются. Для прибавки веса не требуется одинаковый вес всех рабочих подходов. Уменьшенный вручную план «2 из 2» считается полным; незавершённые «2 из 3» не проходят завершение API. Это сохранённые правила, а не новая методика.

Происхождение старых ручных целей до версии 6 восстановить нельзя. Завершённые результаты через API по-прежнему не редактируются. Ограничение журнала 100 занятиями, временный запрет переноса архивного назначения и неизвестный шаг старого снимка остаются. Политика календарных исключений/длительного перерыва, предпросмотр будущего занятия, недельный прогноз, оборудование и общий редизайн требуют отдельных согласований. Следующий небольшой шаг — согласовать читающий предпросмотр следующего нового занятия; автоматически к нему не переходить.
