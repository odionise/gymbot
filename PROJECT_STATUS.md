В журнале собственного туннеля подтверждены разрывы 10:25:35–10:25:49 и 10:28:42–10:29:02 по Москве; есть ошибка DNS resolver timeout. ## Результат API предпросмотра

`GET /api/templates/{template_id}/preview?on_date=YYYY-MM-DD` оценивает одно новое занятие по текущим данным. Дата обязательна: от сегодня до конца следующей недели по часовому поясу пользователя. Она не переносится автоматически; будущие промежуточные тренировки не предполагаются выполненными.

- `ready`: предварительные цели и временное объяснение. Силовое показывает вес, подходы, повторы и ПДО, временное — минуты; неприменимые поля имеют NULL.
- `existing`: ссылка на незавершённое занятие этого дня программы либо занятие на указанную дату. Его цели/ручные изменения не пересчитываются.
- `blocked`: отпуск, пустой день или недостаточная настройка движений. Неизвестное движение не создаётся и не классифицируется по названию. Проблема другого собственного дня учитывается, если влияет на общий силовой объём; только минуты от неё не зависят.
- Ответ имеет `provisional: true`, `persisted: false`, дату расчёта, часовой пояс, параметры недели с `source: saved / calculated` и `Cache-Control: no-store`. Новые идентификаторы занятий, циклов, недель и снимков не генерируются.
- Telegram-подпись проверяется общей функцией без регистрации пользователя. Чужой/удалённый/неизвестный день и подписанный неизвестный пользователь получают 404; ошибочная аутентификация — 401; отсутствующая/неверная/недопустимая дата — 422.

Решение о неделе теперь рассчитывается отдельно от сохранения и используется обоими путями. Проекция пропущенной разгрузки влияет на предпросмотр объёма и возвращения в памяти; прежняя отметка в БД не меняется. Существующая неделя сохраняет свои параметры. Формулы этапа 2 и идентичности истории этапа 1 сохранены; при одинаковом времени завершения история упорядочивается также по существующему ID.

Новый GET использует PostgreSQL REPEATABLE READ + READ ONLY либо SQLite query_only и явную читающую транзакцию. Autoflush отключён; нет flush/commit, пробных записей с откатом, создания пользователя или автоматической привязки движения. Завершение чтения восстанавливает режим соединения для обычной работы.

## Границы и следующий шаг

Предпросмотр не закрепляет цели и не резервирует занятие. При изменении входных данных настоящий план может отличаться; создание по-прежнему выполняется отдельным действием. Сохраняются текущие правила разных весов, неполных/ручных планов, фазы и ПДО. Прогноза всех занятий недели, выбора произвольного календарного периода, новой методики и редизайна нет.

Интерфейс подключается отдельным согласованным этапом: обычный App.refresh вызывает /sessions/today, который создаёт занятия. Новый предпросмотр нельзя подключать через этот путь и объявлять всё открытие приложения читающим. До такого согласования UI не менять.
